# 管理工作台 8 Tab · 多源对比 → 最优界面内容（2026-08-01）

> 按方法论流程：对 8 个 tab 右侧内容区做**多源竞品对比**，找「行业最优」界面内容，输出各 tab 的优化建议。
>
> **参照锚点（3 源，实际拉取）**：
> 1. **Ant Design ProTable**（ant-design/pro-components 官方源码 + demo）——antd 生态企业级列表页标准
> 2. **Dify**（langgenius/dify 源码 + i18n）——Agent 平台资源管理页实证
> 3. **n8n / LangSmith**（此前工作流分析已拉）——编排平台管理页

---

## 第 3 步 — 参照锚点核实

### 锚点 1：Ant Design ProTable（企业级列表页标准）

ProTable 是 antd 生态的**标准管理列表**，其工具栏由三部分组成：

| ProTable 能力 | 说明 | 本项目现状 |
|--------------|------|-----------|
| **search** 搜索表单 | 顶部搜索，支持多字段 | ✅ 有（单框搜索） |
| **toolBarRender** 操作按钮 | 新建/批量操作按钮区 | ✅ 有 |
| **options** 表格设置 | `density`（密度）/`fullScreen`（全屏）/`reload`（刷新）/`setting`（列设置） | ❌ **全缺** |
| **rowSelection** 批量选择 | 多选 + 全选/反选 | ✅ 有（仅全选） |
| **列排序/筛选** | columns 支持 sorter/filter | ⚠️ Agent/Team 有，其余无 |

**关键结论**：ProTable 标准工具栏 = 搜索 + 操作按钮 + **表格设置（密度/全屏/刷新/列设置）**。本项目 8 个 tab **完全没有 options 区**。

### 锚点 2：Dify 资源管理页

Dify 的 agent 名册（roster）和列表页证实两个标准能力：
- **排序**（`roster.sort.recentlyCreated`/`optionsLabel`）——列表页提供显式排序选项
- **过滤**（`filter.all`/`onlyYourThreads`）——分类过滤

### 锚点 3：n8n / LangSmith 管理页

- n8n workflows 列表：搜索 + **状态标签** + **卡片/列表切换**
- 编排平台列表普遍有：刷新、统计计数（总条数）

### 三源共性 → 行业最优特征

| 特征 | ProTable | Dify | n8n | **本项目** |
|------|----------|------|-----|-----------|
| 搜索 | ✅ | ✅ | ✅ | ✅ 全部有 |
| 新建/批量按钮 | ✅ | ✅ | ✅ | ✅ 全部有 |
| **表格设置（密度/全屏/刷新/列设置）** | ✅ | ⚠️ 刷新有 | ✅ 刷新 | ❌ **全缺** |
| **显式排序** | ✅ sorter | ✅ sort 选项 | ⚠️ | ⚠️ 仅 Agent/Team |
| **状态标签** | ✅ | ✅ | ✅ | ✅ 有（彩色圆点） |
| **刷新** | ✅ reload | ✅ | ✅ | ❌ 仅 Agent/Team 错误重试 |
| **计数/统计** | ⚠️ | ✅ 列表总数 | ✅ | ❌ 无 |
| **空状态设计** | ✅ | ✅ empty | ✅ | ✅ 有 |

## 第 4 步 — 逐 tab 对比 + 最优建议

### 通用缺失（8 tab 全部）

| 缺失能力 | 行业依据 | 建议 |
|---------|---------|------|
| **表格设置区**（密度/全屏/刷新/列设置） | ProTable options 标准 | 工具栏右侧加 ⚙（列设置）+ ⟳（刷新）+ ⛶（全屏）——**最高价值** |
| **列表计数**（共 N 条） | Dify/n8n 均有 | 工具栏或表底显示「共 N 条」 |
| **显式排序** | ProTable sorter + Dify sort | 表头可点击排序（名称/状态/创建时间） |

### 逐 tab 特有问题

**1. 提示词（Prompt）**
- ✅ 搜索 + 全部分类 + 全部状态 + 批量 + 新建——**标准**，接近最优
- ⚠️ 缺：表格设置、计数、排序
- **最优形态**：加「共 N 条」计数 + 表头排序（名称/状态）

**2. 输出约束（Output）**
- ✅ 搜索 + 分类 + 状态 + 批量 + 新建
- ⚠️ 缺：同提示词 + **内容列过窄**（约束正文被截断，应加 hover 展开/弹窗预览）
- **最优**：内容列加「预览」按钮（点击弹窗看完整约束）

**3. 工具（Tool）**
- ✅ 搜索 + 分类 + 状态 + 批量 + 新建；内置标记 ✅
- ⚠️ 缺：表格设置、排序
- **最优**：分类列显示统计（「内置工具 (5)」徽章数）

**4. MCP**
- ⚠️ **无分类筛选**（列表无类型筛选）——8 个 tab 中 2 个缺分类之一
- ⚠️ 缺：表格设置、计数
- **最优**：加「全部分类（全部类型/stdio/sse）」筛选——**对照 Dify 有类型过滤**

**5. Skills**
- ✅ 最全：搜索 + 分类 + 状态 + 批量 + **导入 SKILL.md** + 新建
- ⚠️ 缺：表格设置、排序
- **最优**：加「已选工具数」列（展示 skill 绑定的工具/MCP 数量，对齐 Dify roster 详情）

**6. Agent**
- ✅ 有排序（handleSort）；⚠️ **无分类筛选**（只有状态）
- ✅ 运行中禁删保护、测试按钮
- **最优**：加「按团队筛选」下拉（Agent 归属团队，对齐 Dify roster 过滤）——**当前无团队过滤，列表混杂**

**7. 团队（Team）**
- ✅ 搜索 + 分类 + 状态 + 批量 + 新建；成员数徽章 ✅
- ⚠️ 缺：表格设置、排序、**工作流绑定状态列**
- **最优**：加「工作流」列（✓ 已绑定 / — 未绑定），对齐「团队需 workflow 才能跑」的语义

**8. 工作流（Workflow）**
- ❌ **非列表**——只有团队下拉进入图编辑，无工作流列表
- **最优**（对齐 n8n/Dify）：**加工作流列表页**（名称/团队/节点数/状态/更新时间），可新建/编辑/删除，而非仅团队下拉
- ⚠️ 这是 8 tab 中最偏离行业标准的

| P2 | 输出约束内容预览 | 约束正文可读性 |

## 结论

8 个 tab 的**基础列表能力达标**（搜索/筛选/批量/新建/状态标签/空状态），但对照 ProTable + Dify + n8n 三个行业参照，**普通缺失 3 项**：

1. **表格设置区**（刷新/密度/列设置）——8/8 全缺，ProTable 标配
2. **列表计数**（共 N 条）——8/8 全缺，Dify/n8n 标配
3. **显式排序**——仅 Agent/Team 有，6/8 缺

**最偏离行业的是工作流**：它根本不是列表页，只有团队下拉进入图编辑——n8n/Dify 都有完整的工作流列表（名称/状态/更新时间/操作）。

**方法论价值**：这次对比把「界面内容」从「凭感觉」变成「对照 3 源共识」——ProTable 定义工具栏标准、Dify/n8n 证实排序/计数/过滤是标配。多源一致 → 判定可信。

# 工作台 8 tab 内容区域（表格列 + 单元格渲染）设计合理性分析（2026-08-02）

> 按 `docs/design-review-methodology-2026-08-01.md` 七步流程，聚焦工作台配置管理 tab 的**内容区域**（表格列、行内容渲染、空状态；workflow tab 为编辑器形态），不覆盖工具栏（⭐2 已评审）与操作区（⭐4 已评审）。
> 依据：7 个 `*Management.tsx` 源码逐行核实 + wireframes/before-after 两份设计文档 + n8n/Dify 竞品源码实测。

## 一、分析对象（五要素）

- **对象**：AgentStudio 工作台 7 个资源表格（agents/prompts/outputs/tools/mcp/skills/teams）+ workflow tab（编辑器形态，非表格）
- **用户**：配置管理用户（开发/运维）
- **场景**：在资源列表中识别、对比、定位资源
- **目标**：每列承载可读信息，帮助用户判断「这是什么、什么状态、新旧、能否直接用」
- **验收**：逐列可回答「谁会读这列、读出的信息是否有决策价值」；与竞品实装对照

## 二、三问判定

1. **要做**：列设计影响信息可读性，用户每天浏览；✅ 做
2. **可验证**：逐列反向追踪消费点 + 竞品源码实装对照，✅ 可验证
3. **非镀金**：列增删改是高频视觉改动，成本低价值直接，✅ 非镀金

### 3.2 单元格渲染模式（实测 `<td>`）

| 列类 | 实现 | 一致性 |
|---|---|---|
| 名称 | 全部 `font-semibold` 纯文本，**无截断无 tooltip**（Dify 为 truncate+Tooltip） | 7 表一致但均不防长名溢出（table-fixed 下超宽被挤/溢出） |
| 描述/内容 | `max-w-[300px] ellipsis + title` 截断（tool:100 / output:89 / mcp:100 / skill:142） | ✅ 4 表一致 |
| 分类 tag | prompt/output 恒 `wsta-tag-indigo`；tool/skill 恒 accent chip；team 用 `getCategoryTagClass` 动态多色 | ⚠️ **三种形态不统一** |
| 状态 | 全部 dot badge（green/gray/red 语义色） | ✅ 7 表一致，与 n8n 状态点同构 |
| 版本 | `font-mono` 原值直出（v1.0.0） | 4 表一致（值零信息） |
| 数量（team 成员数） | 圆形计数 chip | ✅ 唯一数量列，对应 Dify 字数/命中数列 |
| 时间（team createdAt） | `font-mono` 原串直出（item.createdAt 未格式化） | ⚠️ 仅 1 表有；skill 导入处 `slice(0,10)` 截串格式不可控 |
| 空状态 | 图标+标题+搜索/普通双语描述，7 表同构 | ✅ 一致 |
| 错误态 | agent/team 有 error banner+retry；其余 5 表无 error 态 | ⚠️ 不一致（hook 层是否暴露 error 待查） |
| 内置标记（tool） | 名称「内置」chip + 复选框 disabled + 操作列「—」（tool:93,97,104） | ✅ 符合 wireframes 设计 |

关键事实：
- **时间列仅 teams 有**（创建时间），其余 6 个表格无任何时间信息
- **版本列 4/7 有**（agent/tool/mcp/skill），prompts/outputs/teams 无——形态不统一
- 描述列 3/7 有（tool/mcp/skill），tool 有 `max-w-[300px] ellipsis + title` 截断，agent 名称列无截断
- 「运行中 Agent 禁删」守卫已实现（useAgentManagement.ts:86 单项 / :99 批量），但 UI 菜单项**无 disabled 视觉态**（AgentManagement.tsx:74），为操作后提示非操作前禁用

## 四、多源参照（源码级实测）

### 4.1 n8n WorkflowCard.vue ✅ 源码实测（n8n-io/n8n@main，SHA b3eb36c）

n8n 工作流列表为卡片视图（= 行级等价物），行内容展示：
- **名称**（heading）
- **更新时间（TimeAgo 相对时间）+ 创建时间（日期）**——「Updated X | Created Y」
- **状态**：published 指示点 + archived 标签
- 标签 tags（截断 3 个 + 展开）
- ⋮ 操作菜单（N8nActionToggle）
- **无版本列、无描述列**（名称即唯一身份信息）

### 4.2 Dify DocumentTableRow.tsx ✅ 源码实测（langgenius/dify@main，SHA 586eb65）

文档列表表格列：
- ☐ 复选框 + **序号**（index+1）
- **名称**（图标 + truncate + Tooltip 全文）
- 切分方式 / 字数（k 格式化）/ 命中数（k 格式化）
- **创建时间**（formatTime created_at）
- 状态（StatusItem）
- 操作（Operations ⋮ 下拉）
- **无更新时间、无版本、无描述列**

### 4.3 既有竞品分析文档 ✅（design-review-workspace-tabs-competitor-analysis-2026-08-01.md）

- 显式排序：ProTable sorter + Dify sort，可排序列含「名称/状态/**创建时间**」
- 搜索 + 分类 + 状态筛选 + 批量 + 新建 = 行业标准

## 七、结论与建议

| 优先级 | 建议 | 依据 |
|---|---|---|
| **P1** | 6 个表格补「更新时间」列（相对时间），与 teams 及 v4 设计对齐 | ✅ n8n/Dify 双源实测 + v4 已设计未落地 |
| **P1** | 版本列移除，或改展示真实版本来源（如版本快照数） | ✅ 竞品 0/2 + form 级评审 0/4 源，信息量为零 |
| **P2** | 名称列统一截断 + tooltip（对齐描述列的 `max-w-[300px] ellipsis + title` 写法） | ⚠️ Dify 实测 truncate+Tooltip；7 表均无防溢出 |
| P2 | 分类 tag 统一视觉形态（team 的动态多色 or 全表统一色） | ⚠️ 同工作台内三种形态并存 |
| P2 | teams 时间列格式化统一（避免 font-mono 原串直出） | ⚠️ 内部一致性 |
| P3 | agent 菜单「运行中」删除项加 disabled 视觉态 | 守卫已实现，缺操作前禁用 |
| P3 | workflow tab 补列表入口（v4 已设计） | 一致性 |
| 待 v4 排期 | 操作列行内化 / 表头排序 / 分类计数 / 预览按钮 / 工具绑定列 / 团队工作流列 / 团队筛选 / 类型筛选 | v4 设计已定，未落地（P0-P1 结论维持） |

## 八、方法论沉淀

1. **设计稿会超前于代码**：v4 已设计「更新时间」列但未落地，分析必须以代码实装为准、设计稿作对照，两者脱节点本身就是发现
2. **列级竞品证据必须源码实测**：竞品文档的表级结论不覆盖列内容；本次 n8n/Dify 各拉一个行渲染组件即定案（版本 0/2、时间 2/2）
3. **「内部信息一致性」是独立判定维度**：teams 有创建时间而其他 6 表没有；分类 tag 三种形态——同一工作台内形态不统一，即使无竞品参照也应统一
4. **「内容区域」= 列 + 单元格渲染 + 空状态**：列头合理不等于行内容合理（本次发现名称列无截断、时间未格式化、tag 色不统一均在渲染层）；空状态 7 表一致是本次唯一全绿项
